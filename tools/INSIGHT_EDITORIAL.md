# AI·IT 인사이트 편집 기준

독자는 재학생과 처음 방문한 일반 독자다. 목적은 신기술의 이해, 탐구, 수업과 프로젝트로의 연결이다. 모집 광고와 취업 홍보 문구로 본문을 채우지 않는다.

## 월·수·금 발행 절차

1. 한국시간 실행일을 확인하고 `git pull --ff-only` 후 기존 글과 오늘 발행 여부를 확인한다. 같은 날짜에 두 번 발행하지 않는다.
2. 최근 10일 내 기술 변화에서 중복되지 않는 주제를 찾는다. 공식 발표와 문서를 실제로 열어 읽는다. 제목·검색 요약만으로 글을 만들지 않는다. 발표일과 보도일을 혼동하지 않는다. 충분한 근거가 없으면 발행하지 않는다.
3. 확인된 사실, 일반적인 기술 원리, 직접 제안하는 실습을 구분한다. 타 대학·학교·교수·학생 관련 홍보 기사는 제외한다. 제품 성능과 벤치마크를 추측하지 않는다.
4. 독자가 무엇을 이해하고 직접 시도할 수 있는지부터 설계한다. 용어 정의, 구체적인 데이터 흐름, 대안 비교, 작동 예, 한계, 과목의 기술과 연결하는 실습, 평가 기준을 포함한다. 특정 기술이 실제 교과목으로 개설되었다고 확인 없이 주장하지 않는다.
5. 본문 3,000~6,000자 이상을 기준으로 충분히 설명하되 반복 문장으로 길이를 채우지 않는다. 필요하면 더 길어도 된다. 절은 최소 6개, 공식 근거 문서는 최소 2개. 주장 옆에 해당 문서 링크를 연결한다. 긴 원문 인용은 피하고 독자적인 설명과 실습을 중심으로 쓴다.
6. 비교표·구체적인 예제·실습 절차 중 독자의 이해에 도움이 되는 것을 포함한다. 실행하지 않은 코드는 의사코드 또는 설계 예시로 표시한다. 실습 수치는 제안과 실제 측정값을 구분한다.
7. `data/posts.json`의 editorialVersion 2 글 형식으로 임시 JSON을 만든다. 기존 URL과 글을 삭제하지 않는다. 필드: slug, date, tag, title, excerpt, source, sourceUrl, references[{title,url}], connection, learningPoints[], projectPrompt, sections[{heading,paragraphs,선택적 bullets/table/code/references}], editorialVersion:2.
8. `python tools/generate_post.py --input 임시JSON`으로 발행 데이터를 검증·추가한다. `python tools/build_site.py`로 생성하고 제목·본문·링크·출처·사이트맵·RSS를 확인한다. 기계적 검사 통과가 사실 확인을 대신하지 않는다.
9. 변경을 커밋·푸시하고 실제 공개 URL과 배포 결과를 확인한다. 게시 시각은 작업 완료에 따라 오전 6시 이후일 수 있다.

## 금지하는 표현과 패턴

- “자동 발행 안내”, “학과 홍보용”, “제목으로 확인되는 기술 흐름”처럼 생성 과정을 설명하는 상투 문구
- 본문 대신 소스 링크에서 알아서 확인하라는 안내
- 실제로 하지 않은 교수 검토, 실험, 측정, 현장 적용을 했다고 주장
- 주제와 무관하게 반복되는 포트폴리오·취업·원서접수 홍보
- 이전 글의 제목만 바꾸고 같은 내용 재사용

## 자동화 구성

Codex의 `학과 AI·IT 인사이트 심층 발행` 예약 작업이 공식 자료 조사와 글 작성을 담당한다. 로컬 작업이므로 PC와 Codex가 실행 가능한 상태여야 한다. GitHub Actions는 커밋 후 검증·정적 페이지 생성·배포만 담당한다. 제목 기반 자동 생성은 폐기했다.
